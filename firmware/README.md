# Прошивка

Прошивка для STM32G431 на основной плате. Сейчас готов каркас: вспомогательные функции,
конфигурация ШИМ, параметры моторов и тесты. FOC, модель мотора и драйверы периферии
будут дальше.

## Главное правило

`src/foc/` не зависит от регистров и HAL. Шаг FOC получает измеренные токи и угол и
отдаёт скважности. Поэтому **один и тот же код** собирается:

- под ARM, в прошивку;
- под ПК, в симулятор и юнит-тесты.

Сначала математику и регуляторы проверяю на модели мотора на ПК, потом подключаю
периферию и перехожу к стенду.

## Сборка

Нужны CMake 3.20 или новее и компилятор C. Из корня репозитория:

```sh
cmake -S firmware -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Кросс-сборка под STM32G431 проверяет, что в `src/foc/` не попало ничего, что работает
только на ПК. Нужен `arm-none-eabi-gcc`:

```sh
cmake -S firmware -B build-arm -DCMAKE_TOOLCHAIN_FILE="$(pwd)/firmware/cmake/arm-none-eabi.cmake" -DCMAKE_BUILD_TYPE=Release
cmake --build build-arm --parallel
```

Оба варианта запускаются в GitHub Actions на каждый push.

Проверить, что библиотека собрана под Cortex-M4 с аппаратным FPU:

```sh
arm-none-eabi-readelf -A build-arm/src/foc/libfoc.a
```

Ожидаются `Tag_CPU_arch: v7E-M`, `Tag_FP_arch: VFPv4-D16` и
`Tag_ABI_VFP_args: VFP registers`. Время шага FOC всё равно нужно мерить на самом МК.

## Структура

```
firmware/
  CMakeLists.txt        на ПК: libfoc и тесты; под ARM: только libfoc
  cmake/
    arm-none-eabi.cmake тулчейн Cortex-M4F, hard-float
  src/foc/              не зависит от платформы
    foc_config.h        ШИМ 48 кГц, период, пределы скважности (как в CubeMX.ioc)
    foc_util.c/.h       wrap_pi, clamp, константы
    motor_params.c/.h   параметры моторов для модели и регуляторов
  test/                 юнит-тесты: свой маленький харнесс и CTest
    test_util.h         CHECK, CHECK_NEAR
    test_harness.c      проверка самого харнесса
    test_foc_util.c     wrap_pi, clamp, согласованность конфигурации
```

Что появится дальше:

| Модуль | Что делает |
|---|---|
| `transforms` | преобразования Кларка и Парка, прямые и обратные |
| `svpwm` | пространственно-векторная модуляция (min-max) |
| `pi` | PI-регуляторы с anti-windup и ограничением вектора напряжения |
| `foc` | шаг управления и машина состояний |
| `observer`, `startup` | оценка угла по ЭДС с PLL, старт без датчика |
| `drivers/` | TIM1, АЦП токов, энкодер AS5047P, DRV8323 по SPI, защиты |
| `comms/` | приём DShot600, телеметрия по UART, команды для стенда |
| `sim/` | модель мотора, инвертора и датчиков для прогонов на ПК |

Модель мотора будет в **неподвижных координатах αβ**, а не в dq. Если моделировать
мотор сразу в dq, модель и регулятор используют один и тот же угол, и ошибка знака в
преобразовании Парка может взаимно сократиться: в симуляторе всё крутится, на железе нет.

Фреймворка для тестов нет намеренно: каждый тест - отдельный исполняемый файл,
ненулевой код возврата означает провал. Зависимостей ноль, CI не ломается от чужих
обновлений.

## Порядок работы

1. `transforms` и тесты: Кларк, Парк и обратно дают исходный вектор.
2. `svpwm` и тесты: сумма скважностей, линейный диапазон до `Vdc/√3`.
3. `pi` и тесты: насыщение и отсутствие windup.
4. Модель мотора по формулам из [теории FOC](../docs/foc-theory.md), §11.
5. Прогоны на модели: скачок тока `iq*`, разгон, реверс, насыщение по напряжению.
6. Прогон на параметрах дрон-мотора: 3,5 кГц электрической частоты при шаге 20,8 мкс.
   Без компенсации задержки момент падает, с ней нет.
7. Наблюдатель и старт без датчика против модели, где истинный угол известен точно.

Параметры мотора в `motor_params.c` пока оценочные. Для стендового мотора MN2212 их нужно
измерить (R, L, kV) и внести перед настройкой регуляторов. Коэффициенты пересчёта токов
задаются по шунтам 20 мОм и усилению CSA, подробности в
[памятке по запуску платы](../hardware/dev-board/bring-up.md).

## Первый запуск на железе

Не FOC, а проще: МК прошивается по SWD, мигает светодиод, UART отвечает. Силовая часть при
этом полностью обесточена.

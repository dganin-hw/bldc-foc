# Архитектура системы

Конечная цель: квадрокоптер на своих регуляторах, управление с RC-пульта.

## Кто с кем разговаривает

```
   пульт с ELRS
          │ 2,4 ГГц
          ▼
   приёмник ELRS ──CRSF (UART)──► полётный контроллер (покупной, Betaflight)
                                        │   IMU, контур угловой скорости,
                                        │   контур угла, микшер, failsafe
                                        │
                             ┌──────────┴──────────┐
                             │ DShot600 ×4         │ UART (телеметрия ESC)
                             ▼                     ▲
                    ┌────────────────────────────────────┐
                    │   4-in-1 FOC ESC (этот проект)     │
                    │  канал 1 │ канал 2 │ 3 │ 4         │
                    │  свой FOC на каждый мотор          │
                    └────────────────────────────────────┘
                             │ ×4 фазы
                             ▼
                        4 мотора
```

## Что покупаю, что делаю сам

| Узел | Решение | Почему |
|---|---|---|
| Пульт и приёмник | покупные, ELRS | своё радио - отдельный проект, и надёжность хуже |
| Полётный контроллер | покупной, любой с Betaflight (F4/F7) | IMU, контуры стабилизации и failsafe - задача сопоставимой сложности |
| 4-in-1 ESC | свой | это и есть проект: силовая часть, FOC, работа без датчика, DShot |
| Рама, моторы, пропеллеры, LiPo | покупные | |

### Почему полётный контроллер покупной

Квадрокоптер - это управление моторами плюс стабилизация аппарата. Это две разные
системы. Если делать обе сразу, при первом же «дрон дёргается» будет непонятно,
виноват FOC, наблюдатель, фильтр IMU или коэффициенты. Принцип простой: не
отлаживать два неизвестных одновременно.

Покупной FC с Betaflight заодно работает как инструмент отладки: вкладка Motors
крутит моторы по одному, Blackbox пишет логи, телеметрия оборотов из ESC видна сразу.

Свой FC можно сделать отдельным проектом. Он встанет в ту же систему без переделок,
потому что интерфейс к ESC стандартный (DShot).

## Интерфейс между FC и ESC

### DShot600: команды

Цифровой протокол, кадр 16 бит: 11 бит значения, 1 бит запроса телеметрии и 4 бита CRC.
На 600 кбит/с бит длится 1,67 мкс, единица и ноль отличаются скважностью
(примерно 75% и 37%).

Приём: таймер в режиме захвата по обоим фронтам с DMA, разбор кадра в прерывании.
Программного разбора по ножке нет.

Почему не аналоговый ШИМ 1000-2000 мкс: DShot точнее, не требует калибровки, имеет
CRC и поддерживает команды (реверс, бипер, сохранение настроек).

### Двунаправленный DShot: обороты обратно

ESC отвечает в ту же линию значением оборотов (eRPM). Betaflight использует это для
RPM-фильтра, настроенного точно на частоту вращения каждого мотора. Это заметно
улучшает полёт.

Реализация: сразу после приёма кадра линия переключается на выход, ответ кодируется
GCR. Здесь нужен точный тайминг.

### Телеметрия по UART

Отдельная линия, стандартный формат KISS/BLHeli: напряжение, ток, потреблённая
ёмкость, температура, обороты. Для настройки на стенде есть ещё свой расширенный
кадр для скрипта на ПК.

## Сколько микроконтроллеров в 4-in-1

Базовый вариант: четыре независимых канала, у каждого свой STM32G431. Общие только
силовая шина, разъёмы и линия телеметрии. Доводы:

1. **Таймеры.** Мотору нужен advanced timer с тремя комплементарными каналами,
   dead-time и входом аварийного отключения. У G431 их два (TIM1, TIM8).
2. **Время.** При ШИМ 48 кГц на период приходится около 20 мкс, один шаг FOC
   занимает 5-8 мкс. Четыре мотора на одном G431 не помещаются.
3. **Отказоустойчивость.** Если сгорит один канал, остальные продолжат работать,
   а при отладке выгорает один транзистор, а не весь регулятор.

Второй вариант, который сейчас прорабатывается: два STM32G474, по два мотора на
каждый, ШИМ через HRTIM. Он экономит два контроллера, но требует расписания АЦП на
два мотора. Число МК выберу по измеренному времени шага FOC. Подробности в
[черновике 4-in-1 ESC](../hardware/esc-4in1/README.md).

## Порядок сборки системы

1. Основная плата, мотор MN2212 и энкодер на стенде: FOC с датчиком.
2. Тот же стенд: наблюдатель без датчика, эталон угла берётся с энкодера.
3. Дрон-мотор без датчика на том же стенде: проверка на реальных оборотах.
4. DShot: покупной FC крутит один мотор через вкладку Motors.
5. Плата 4-in-1: тот же канал ×4.
6. Дрон в сборе, **без пропеллеров**, проверки на земле.
7. Пропеллеры, привязь, первый полёт.

Каждый шаг проверяю отдельно.
